# Правила работы с Figma

Документ для агента по дизайну и для ручной работы с макетами Figma в рамках Content Factory / сайт Энтузиаст.

---

## 1. Формат ссылки Figma

Используй URL с **node-id**, чтобы указывать конкретный фрейм или компонент:

```
https://figma.com/design/{fileKey}/{fileName}?node-id={nodeId}
```

- **fileKey** — идентификатор файла (сегмент после `/design/`)
- **nodeId** — ID узла, например `42-15` (из query-параметра `node-id`)

Пример:  
`https://figma.com/design/ABC123xyz/Entuziast-Site?node-id=1-42`

---

## 2. Порядок работы при реализации макета

1. **Получить контекст** — по fileKey и nodeId запросить данные макета (Figma MCP: `get_design_context` или аналог).
2. **Разобрать структуру** — Auto Layout, ограничения, размеры, типографика, цвета.
3. **Сопоставить с кодом** — тема сайта: `entuziastov75-child` (PHP, CSS). Использовать существующие классы и компоненты, при необходимости добавлять новые в тему.
4. **Реализовать с 1:1** — вёрстка и визуал максимально соответствуют макету (отступы, шрифты, цвета).
5. **Проверить адаптив** — при наличии макетов для мобильных/планшетов — реализовать брейкпоинты.

---

## 3. Дизайн-токены и стили сайта

- Цвета, шрифты, отступы темы хранятся в CSS темы (переменные, классы).
- При появлении официальной дизайн-системы в Figma — зафиксировать токены в `design/tokens.md` и при реализации опираться на них.
- Не дублировать значения: использовать переменные темы (например `var(--color-teal)` и т.п.).

---

## 4. Code Connect (Figma ↔ код)

При связывании компонентов Figma с компонентами кода:

- Использовать формат и workflow из skill «code connect» (Figma MCP).
- Хранить маппинги и примечания в `design/` при необходимости.

---

## 5. Где править код под макеты

- **Стили:** тема VPS `entuziastov75-child` — `style.css`, `assets/css/`, при необходимости новые файлы в `assets/css/`.
- **Разметка:** шаблоны страниц и частей (PHP) в той же теме.
- Не менять контент и логику агентов (seo-agents) ради только визуала; изменения под дизайн — в теме и статике.

---

## 6. Язык и коммуникация

- Описания, комментарии в коде и коммиты — на русском.
- Названия переменных/классов в коде — на английском (как принято в проекте).
