# Обработка ошибок и retry-стратегия

## Агент 4: agent_4_publish.py

### Retry — два уровня

#### 1. HTTP-транспорт (requests.Session + urllib3.Retry)

| Параметр | Значение |
|----------|----------|
| Попыток | 3 |
| Триггеры | HTTP 500, 502, 503, 504 |
| Задержка | `backoff_factor=1.0` → 1с, 2с, 4с |
| Методы | GET, POST, PUT |

Работает прозрачно — если WP-сервер вернул 502 (nginx-перезагрузка), запрос повторится автоматически.

#### 2. Application-уровень (`_wp_request`)

| Параметр | Значение |
|----------|----------|
| Попыток | 3 (MAX_RETRIES) |
| Триггеры | `ConnectionError`, `Timeout` |
| Задержка | линейная: 1с → 2с → 3с |
| Ранний выход | HTTP 401 (авторизация) и 403 (нет прав) — не повторяем |

### Обработка HTTP-статусов

| Код | Поведение |
|-----|-----------|
| 200, 201 | Успех |
| 401 | `RuntimeError` — неверные WP_USERNAME / WP_APP_PASSWORD |
| 403 | `RuntimeError` — пользователю нужна capability `edit_posts` |
| 429 | Rate limit — повторяем (через retry-сессию) |
| 500–504 | Автоматический повтор (оба уровня) |

### Логирование

- **Консоль**: все шаги с эмодзи (✅ ❌ ⚠️ ⏳)
- **БД**: таблица `publishing_log` (через `_log_to_db`, если есть `content_item_id` в метаданных)
- **Файлы логов**: `logs/seo_agents.log` (через `shared/logger.py`)

## Скрипт деплоя: deploy_to_vps.py

### REST-режим (`--mode rest`)

- Итерирует по услугам из `output/services-patch-data.json`
- POST на `/wp-json/entuziastov75/v1/service-data/{slug}` для каждой услуги
- При ошибке одной услуги — продолжает остальные
- Итоговый отчёт: `✅ N  ❌ M`
- Опция `--dry-run`: показывает что будет отправлено без реальных запросов

### SSH-режим (`--mode ssh`)

- SCP-копирование PHP-файла на VPS
- Требует `VPS_HOST`, `VPS_USER`, `VPS_SSH_KEY` в `config/.env`
